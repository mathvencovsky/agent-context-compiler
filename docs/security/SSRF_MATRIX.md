# Matriz SSRF: caso → teste que prova

Rastreabilidade dos 15 casos de `security/SSRF_TEST_MATRIX.csv` (engineering pack do revisor externo) para os testes do NINA. Para cada caso, o teste prova que o destino proibido **não recebeu nada**: o guard recusa antes de resolver ou de conectar, o transporte gravador fica vazio (ou só tem os saltos permitidos), ou o proxy de egress do navegador responde 403 sem abrir conexão.

Como ler: `arquivo::teste`. Testes marcados `[browser]` rodam com `uv run pytest -m browser` (Chromium); `[integration]` precisam de `make up`; os demais rodam em `make check`.

Peças do produto envolvidas: `app/fetch/guard.py` (validação de esquema, porta, notação de IP, resolução e bloqueio por faixa), `app/fetch/client.py` (conecta no IP validado, segue redirects à mão revalidando cada salto, limites de corpo e prazo), `app/fetch/egress_proxy.py` + `app/fetch/render.py` (todo pedido do Chromium passa pelo guard), `app/fetch/url_secrets.py` (URLs com segredo ou userinfo), `app/retrieve/render.py` (texto de página não forja estrutura do NINA).

## Pendências

- Os itens SEC-001 a SEC-005 do guia v2.0 não estavam no repositório nem no resumo recebido, então não foram mapeados um a um. Pelo resumo, os temas (guard, redirects, userinfo, limites, conteúdo não confiável) estão cobertos pelas linhas 1–15 acima; confirmar o mapeamento quando o texto do guia estiver disponível.
- Não há teste de rede real: tudo usa transporte gravador, resolver falso ou servidores locais em loopback. Isso é intencional (CLAUDE.md: testes nunca tocam a rede externa).
